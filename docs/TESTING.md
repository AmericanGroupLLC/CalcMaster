## Writing tests — guidelines

- **AAA structure** (Arrange / Act / Assert)
- **One assertion focus per test** — ok to have multiple `expect`s when they assert one behavior
- **Test names** describe behavior, not implementation: `it('shows error banner when network fails')`
- **No real network, real disk, real time** in unit/component layers — use fakes
- **Use real implementations in integration** with seeded fixtures and ephemeral storage
- **E2E only for critical user journeys** — keep small, parallelize, retry once on infra flake

## Mock / fake strategy
- Network: {{NETWORK_FAKE}} (msw / mockwebserver / URLProtocol stub)
- Time: {{TIME_FAKE}} (fakeTimers / Clock injection)
- Random: seeded RNG injected via DI
- Storage: in-memory implementation behind the production interface

## Coverage carve-outs
Allowed only for:
- Generated code (e.g. `*.g.dart`, `*.freezed.dart`, GraphQL codegen)
- Native bridge boilerplate that cannot be exercised from tests

Each carve-out must be tagged with a justification comment:
```dart
// coverage:ignore-start
// JUSTIFICATION: generated by build_runner; tested via integration tests
// coverage:ignore-end
```

## Flaky-test policy
- A test that fails non-deterministically twice in 24h is **quarantined** (skipped + tracked in `flaky-tests.md`)
- Quarantine is auto-flagged after 14 days untouched
- Owner has 5 working days to fix or delete
